## 2. /verify orchestrator output schema

**File:** `newleaf-api/src/types.ts` + `newleaf-api/src/orchestrator.ts`

### VerificationResult (returned by POST /verify)

```typescript
interface VerificationResult {
  jobId: string;
  verdict: Verdict;
  evidence: { technical: TechnicalReport; gamma: GammaReport; iv: IVReport; sentiment: SentimentReport };
  debate: { rounds: { bull: ResearcherArgument; bear: ResearcherArgument }[] };
  riskReport: RiskReport;
  suggestedFix?: SuggestedFix;
  marketData?: MarketData;
  cost?: { calls: TokenUsage[]; totalCost: number; totalInputTokens: number; totalOutputTokens: number };
  traces?: LLMTrace[];
  durationMs: number;
  modelMode: ModelMode; // added by route handler
}
```

### Sub-schemas (from Zod definitions in types.ts)

```typescript
interface Verdict { call: 'pass'|'marginal'|'fail'; confidence: number; rationale: string; flipConditions: string[]; }
```

## 5. Pipeline data sources — full inventory

### Spot price / quote
- **Source:** Alpaca Data API
- **URL:** `https://data.alpaca.markets/v2/stocks/{sym}/snapshot`
- **Called in:** `publish-pick.cjs:115`, `newleaf-pipeline.js:198`
- **Auth:** `APCA-API-KEY-ID` + `APCA-API-SECRET-KEY` from `scanner/config.json`

### Options chain (bid/ask/Greeks)
- **Source:** Alpaca Data API (indicative feed)
- **URL:** `https://data.alpaca.markets/v1beta1/options/snapshots/{sym}?expiration_date={exp}&feed=indicative`
- **Called in:** `publish-pick.cjs:124`, `newleaf-pipeline.js:214`
- **NOTE:** `openInterest` hardcoded to `0` — Alpaca does NOT provide OI

### Open Interest
- **Source:** Yahoo Finance via `yfinance` Python lib, served by `scanner/yahoo-svc/option_api.py` on `:5300`
- **URL:** `http://localhost:5300/api/options/{sym}/{expiry}`
- **Called in:** `newleaf-pipeline.js:249` — merged into Alpaca contracts via `mergeOI()`
- **This is the ONLY real OI source in the pipeline**

### Greeks
- **Source:** Alpaca provides delta, gamma, theta, vega, midIV per contract
- **Fallback:** `gamma-analyzer-enhanced.js` estimates gamma via Black-Scholes `estimateGamma(K,S,iv,T)` when Alpaca Greeks are missing

### Gamma walls
- **Source:** Computed locally by `scanner/gamma-analyzer-enhanced.js`
- **Inputs:** Alpaca contracts (Greeks + volume) merged with Yahoo OI
- **Scoring:** 60% OI baseline + 30% OI delta + 10% intraday volume
- **publish-pick.cjs** reads pre-computed walls from R2: `{R2_BASE}/reports/{sym}/latest.json`

### Technical indicators (RSI, Bollinger, SMA, ATR)
- **Source:** Calculated locally from Alpaca daily bars (250 days)
- **RSI(14):** `newleaf-pipeline.js:275` — hand-rolled, no TA-Lib
- **Bollinger(20,2):** `newleaf-pipeline.js:268`
- **SMA(50/100/200):** `newleaf-pipeline.js:266`
- **ATR%:** `newleaf-pipeline.js:321`
- **MACD:** **NOT CALCULATED ANYWHERE in the pipeline.** Values in analysis JSON are LLM-generated estimates.
- **ADX:** **NOT in scanner.** Only computed API-side in `indicators.ts:54`

### Analyst price targets / news headlines
- **Source:** Claude CLI with `--allowedTools WebFetch,WebSearch` inside sentiment-engine.js
- **Claude performs live web searches** for: analyst upgrades/downgrades, price targets, earnings, M&A, regulatory
- **No separate news API in the pipeline.** All news data comes through Claude and Gemini's `googleSearch` tool.

### Earnings calendar
- **Source:** Static local file `scanner/earnings-calendar.json`
- **NOT fetched from any API** — manually maintained or pre-fetched

### Social sentiment
- **Reddit:** `https://www.reddit.com/r/{wsb,options,stocks}/search.json` (no auth)
- **StockTwits:** `https://api.stocktwits.com/api/2/streams/symbol/{sym}.json` (no auth)
- **Grok (X/Twitter):** `https://api.x.ai/v1/chat/completions` model `grok-3-mini`
- **Gemini (Google News):** `@google/generative-ai` SDK, model `gemini-2.5-flash` with `googleSearch` tool

## 8. The publish/render path

### (a) Picks site: newleafsystem.com/picks/analysis/{ticker}

**File:** `src/picks/PickAnalysisPage.jsx`
1. Reads URL param `{symbol}`
2. Fetches `weeklyPicks` (latest by weekId) → finds pick matching symbol → gets `tileId`
3. Fetches `analyses/{tileId}` from Firestore → renders strategyRationale, technicalIndicators, riskAnalysis
4. Fetches `tiles/{tileId}` from Firestore → renders legs, Greeks, P&L
5. Builds payoff diagram client-side from legs data

**Read path:** Firestore `weeklyPicks` → Firestore `analyses/{tileId}` → Firestore `tiles/{tileId}`

### (b) Invest/trading page: newleafsystem.com/trading/strategy/{id}

**File:** `src/trading/pages/StrategyDetailPage.jsx`
1. Reads URL param `{id}` (tileId)
2. Fetches `analyses/{id}` from Firestore (line 82)
3. Finds tile from pre-loaded `tiles` prop
4. Renders analysis + tile data in evaluate/manage mode

**Read path:** Firestore `analyses/{id}` + prop-passed tile data

### (c) PDF report

**Files:** `pipeline/build-enriched-report-data.py` → `pipeline/generate-report.py`
1. Reads `enriched-pick.json` from `pipeline/output/{weekId}/enriched/{slug}.json`
2. `build-enriched-report-data.py` flattens all fields into 100+ template variables
3. `generate-report.py` fills `templates/report-v3.html` with variables → WeasyPrint → PDF
4. PDF saved to `pipeline/output/reports/{symbol}-{strategy}.pdf`
5. Optionally uploaded to R2 via `upload-to-r2.py`

**Read path:** Local JSON file → Python template → WeasyPrint → PDF file → R2 bucket

### What changes if JSON source changes

All three paths read from **Firestore `analyses/{tileId}`** (a + b) or the **local enriched-pick.json** (c). If the analysis JSON schema changes:
- React pages (a, b) will break if field paths change (hardcoded in JSX)
- PDF template (c) will show blank fields if placeholder names change in `build-enriched-report-data.py`

## 9. Pipeline cadence

**File:** `scanner/crontab`

```cron
# Intraday fast pipeline (Alpaca only, every 15 min, 9am-4pm ET Mon-Fri)
*/15 14-21 * * 1-5  scanner/pipeline-fast.js --watchlist

# Daily OI enrichment + watchlist pipeline (every 15 min, executes once/day)
*/15 14-21 * * 1-5  scanner/run-daily-catchup.sh

# Update pick outcomes (6pm ET Mon-Fri)
0 23 * * 1-5  scripts/update-pick-outcomes.js

# Weekly picks email (Sunday 6pm ET)
0 23 * * 0  pipeline/send-weekly-email.js

# Health check (every 5 min)
*/5 * * * *  scanner/check-scheduler-health.sh
```

**Tickers per run:** 144 symbols on watchlist (from `scanner/config.json`)

**Tiles published per week:** Manual process via `node pipeline/publish-pick.cjs`. No automated tile creation in cron. The `create-weekly-picks.js` script exists but is run manually (`npm run picks:preview` for dry-run). Typical volume: **5-10 tiles per week** based on seed data patterns (W07-W15 averaged ~5 picks/week).

**No GitHub Actions, no Firebase scheduled functions, no launchd plists.** Cron is installed via `start.sh` which writes `scanner/crontab` to the system crontab.
