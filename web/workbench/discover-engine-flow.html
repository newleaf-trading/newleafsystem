The deterministic stack — algorithms & services

Each box on the flow chart maps to a real module. None of these call an LLM — they are pure, testable, deterministic code. Tags: code deterministic · data market data · llm uses a model.

How to use it

① Get a trade idea for one stock

newleafsystem.com/workbench/discover-engine.html

Type a ticker (or tap a chip), pick a target DTE → you get the full recommendation: decision (APPROVED / WATCHLIST / NO_TRADE), strategy + legs, payoff chart, risk plan, the gate trace, and the market context it decided from. Deterministic — same inputs always give the same trade.

② Scan the whole universe for setups

newleafsystem.com/workbench/movement-range.html

All 297 names ranked by Setup Quality. The funnel shows why names were excluded (earnings, untested zones, illiquid, weak rail, low score). Each row shows the S/R evidence (touches · holds/rejects · smoothed rate) and a suggested spread. Use the presets (Condor screen · Bullish at support · Bearish at resistance).

③ Run the product flow

newleafsystem.com/workbench/discover.html

The 5-step builder: snapshot → AI-ranked strategies → drill into one → verify → pass/fail verdict → publish. Built on the same /api/recommend engine.

④ Call the API directly

TK=TSLA
EXP=$(curl -s "$BASE/api/snapshot/$TK" -H "X-API-Key: $KEY" \
  | jq -r '.expirations | map(select(.)) | .[0]')
curl -s -X POST "$BASE/api/recommend" \
  -H "Content-Type: application/json" -H "X-API-Key: $KEY" \
  -d "{\"ticker\":\"$TK\",\"expiry\":\"$EXP\"}" | jq '.enginePick.reasoningOverride'

Read enginePick.reasoningOverride (decision · strategy · legs · regime · risk plan), engineSnapshot.gateValues (the score pillars + walls), and reactionFeatures (the S/R rails). cost.totalCost is always 0.

⑤ Data freshness

The scanner pipeline refreshes the R2 reports automatically — fast pass every 15 min during market hours, full OI enrichment at 9:32am ET. movement-range and watchlist read those; the discover pages call the engine live per request.
