Pipeline Cloud Migration

Move the NewLeaf data pipeline from a local Mac scheduler to Google Cloud Platform — eliminating single-machine dependency, enabling auto-scaling, and reducing operational risk.

Yahoo OI Service — already on Cloud Functions
Firestore — already on GCP
Pipeline — local Mac (node-cron)
Scheduler — single point of failure

Deployment Options

Recommended

Option A: Cloud Run

Container-based • HTTP-triggered • Same Firebase project

  • 60-minute timeout — handles daily OI enrichment (10 min) with headroom
  • Full Node.js 20 environment — identical to local
  • Scales to zero — no cost when idle
  • Dockerfile + 1 entrypoint file — minimal new code
  • Same container for all 3 jobs (fast / daily / sync) via HTTP routes
  • Easy local testing: docker run
  • Requires Artifact Registry for container images (~$0.10/mo)
  • Cold start: 3-5 seconds (irrelevant for batch jobs)

Option B: Cloud Functions (2nd Gen)

Implementation Timeline

Day 1

Containerise & Test Locally

Create Dockerfile, cloud-entrypoint.js, .dockerignore. Build and run locally with docker run. Verify fast/daily/sync routes produce correct output.

Day 2

Secrets & Deploy

Push Alpaca, R2, sentiment API keys to Secret Manager. Deploy container to Cloud Run. Configure IAM permissions for Firestore + Secret Manager access.

Day 3

Cloud Scheduler + End-to-End Test

Create 3 Cloud Scheduler jobs (fast, daily, sync). Run one full market-hours cycle. Verify R2 manifest updates, Firestore tiles refresh, scanner page shows fresh data.

Day 4-5

Shadow Run & Cutover

Run cloud and local in parallel for 1-2 trading days. Compare outputs. Once confirmed identical, kill local scheduler. Done.

Migration Risks

Medium

Nasdaq Rate Limiting

Cloud Run uses shared egress IPs. Nasdaq may rate-limit more aggressively than a residential IP. Mitigation: Yahoo fallback is already in place.

Low

Ephemeral Filesystem

Cloud Run /tmp is wiped between invocations. OI history (needed for delta) must be read from R2 instead of local files. One-time code change.

Low

Cold Starts

Container cold start: 3-5 seconds. Irrelevant for batch jobs that run 5-15 minutes. Not a concern.

Recommendation: Cloud Run (Option A)

Cloud Run is the right fit: it handles the 10-minute daily OI enrichment comfortably, uses the same Firebase project as the existing Yahoo OI service and Firestore, costs ~$8/month, and requires only ~100 lines of new code with zero changes to pipeline logic.

  1. Approve Cloud Run as the target platform
  2. Build Dockerfile + HTTP entrypoint (Day 1)
  3. Deploy to newleaf-trading GCP project with Secret Manager (Day 2)
  4. Wire up Cloud Scheduler and test full cycle (Day 3)
  5. Shadow-run alongside local for 1-2 days, then cut over (Day 4-5)
