F3 Weekly Picks Narrative AUTO-FETCH Open /picks →
Steps to Test
  1. Navigate to /picks
  2. Wait for picks data to load (cards should appear in 2-column grid)
  3. The AI narrative should auto-fetch once week data loads — watch for a loading spinner + "Generating narrative..." text above the picks grid
  4. After 2-5 seconds, the narrative card should render with:
    • A market bias pill (e.g., "cautiously bullish" / "neutral" / "bearish")
    • A narrative paragraph explaining the week's picks theme
    • Key themes tags below (e.g., "IV contraction", "earnings season")
  5. Refresh the page — narrative should load from cache (instant, no loading spinner)
Expected API Call (DevTools)
POST /api/picks-narrative // Request body: { "picks": [...], "weekId": "2026-W20", "modelMode": "budget-qwq" } // Response: { "narrative": "...", "marketBias": "...", "keyThemes": [...] }
Pass Criteria
PASS if: Narrative text appears above picks grid, market bias pill is colored, key themes render as tags, and no console errors related to the narrative hook.
Fail Indicators
FAIL if: Loading spinner spins indefinitely, red error message appears, narrative section is completely missing, or Network tab shows 4xx/5xx on /api/picks-narrative.
Verification Checklist
  • Narrative auto-fetches on page load
  • Market bias pill rendered with color
  • Narrative text is coherent and references this week's picks
  • Key themes tags appear below narrative
  • Second page load uses cache (no new API call in Network tab)
  • No console errors
F2 Live AI Verdict Explanation MANUAL TRIGGER Open /invest/positions →
Prerequisites

You must have at least one active/owned position to see PositionCards with verdicts.

Steps to Test
  1. Navigate to /invest/positions
  2. Find any position card showing a verdict pill (HOLD, MONITOR, EXIT, etc.)
  3. Look for the "AI explain" button at the bottom of the card
  4. Click "AI explain" — button should change to "Analyzing..."
  5. After 2-5 seconds, an AI explanation should appear in italic green text below the verdict, prefixed with a green "AI" badge
  6. Click "AI explain" on a different position to verify per-position isolation
Expected API Call (DevTools)
POST /api/verdict-explain // Request body: { "ticker": "AAPL", "verdictState": "HOLD", "marketData": { spot, ivRank, dte, pnlPct }, "modelMode": "budget-qwq" } // Response: { "explanation": "...", "confidence": 0.82 }
Pass Criteria
PASS if: Clicking "AI explain" fetches and displays a natural-language explanation specific to that position's ticker and verdict state. Explanation appears inline below the verdict.
Fail Indicators
FAIL if: Button does nothing, stays on "Analyzing..." forever, explanation is generic/wrong ticker, or Network tab shows error on /api/verdict-explain.
Verification Checklist
  • "AI explain" button visible on position cards
  • Button changes to "Analyzing..." on click
  • Explanation appears with green AI badge
  • Explanation references the correct ticker and verdict
  • Works independently per position card
  • Cached on re-click (no duplicate API call)
  • No console errors
F4 Strike Comparison Cards MANUAL TRIGGER Open /invest →
Prerequisites

You need a strategy in evaluate mode (unowned). Navigate to any strategy from the /invest landing page or picks.

Steps to Test
  1. Navigate to /invest and click into any strategy tile to open /invest/strategy/:id
  2. Verify you're in evaluate mode (tabs show: Setup, Thesis, Chart, Risks, Sentiment)
  3. Click the "Setup" tab (usually default)
  4. Scroll below the Position Legs table
  5. Find and click the "Compare Alternative Strikes" button
  6. Watch for loading state: spinning icon + "Analyzing alternative strikes..."
  7. After response (3-8 seconds), verify:
    • Section title: "Alternative Strike Selections"
    • A reasoning paragraph explaining the AI's analysis
    • A 3-column grid of alternative cards
    • Each card shows: name, legs diff, tradeoff text, PoP/MaxProfit/MaxLoss metrics
    • One card may have a green border + "Recommended" label
Expected API Call (DevTools)
POST /api/strike-compare // Request body: { "ticker": "SPY", "currentLegs": [{ type, strike, expiry, side }], "spot": 542.30, "strategy": "iron_condor", "modelMode": "budget-qwq" } // Response: { "alternatives": [ { name, legsDiff, tradeoff, pop, maxProfit, maxLoss, recommended } ], "reasoning": "..." }
Pass Criteria
PASS if: Alternative strike cards render in a grid below the legs table, each showing meaningful tradeoff analysis with numerical metrics. At least one alternative should be marked as recommended.
Fail Indicators
FAIL if: Button missing entirely, loading never completes, red error box appears, alternatives are empty, or metrics show NaN/undefined values.
Verification Checklist
  • "Compare Alternative Strikes" button visible in Setup tab
  • Loading state displays correctly
  • Alternative cards render in grid layout
  • Each card has legs diff, tradeoff text, and metrics
  • Recommended card has green border
  • Reasoning paragraph is coherent
  • No console errors
F7 Earnings/Dividend Risk Alerts MANUAL TRIGGER Open /invest →
Prerequisites

Same as F4 — open any strategy in evaluate mode, then switch to the Risks tab.

Steps to Test
  1. Navigate to /invest and click into any strategy tile
  2. Click the "Risks" tab
  3. Find and click the "Check Event Risks" button at the top of the tab
  4. Button should show "Checking..." with reduced opacity while loading
  5. After response (2-5 seconds), verify:
    • Alert cards for each detected event (earnings, dividends, ex-dates)
    • Each alert shows: severity pill (HIGH = red, MEDIUM = orange, LOW = gray), event type, description, and recommendation
    • IV Crush Risk card (purple-tinted) showing crush risk assessment
  6. Try on a ticker with upcoming earnings (e.g., NVDA, AAPL) — should show high-severity alerts
Expected API Call (DevTools)
POST /api/event-risk // Request body: { "ticker": "NVDA", "expiry": "2026-06-20", "strategy": "iron_condor", "legs": [...], "modelMode": "budget-qwq" } // Response: { "alerts": [ { severity: "high", type: "earnings", description: "...", recommendation: "..." } ], "ivCrushRisk": { summary: "...", level: "high" } }
Pass Criteria
PASS if: Event alerts render with proper severity coloring, descriptions are ticker-specific, recommendations are actionable, and IV crush risk section appears. Tickers near earnings should show HIGH severity.
Fail Indicators
FAIL if: Button stays on "Checking..." forever, no alerts render even for tickers with upcoming events, severity pills are missing/wrong color, or Network tab shows error.
Verification Checklist
  • "Check Event Risks" button visible in Risks tab
  • Loading state shows correctly
  • Alert cards render with severity pills
  • Severity colors: HIGH=red, MEDIUM=orange, LOW=gray
  • Each alert has description + recommendation
  • IV Crush Risk section appears (purple card)
  • No console errors
F1 AI Adjust Recommendations MANUAL TRIGGER Open /invest/positions →
Prerequisites

You must have an owned/active position. Navigate from Positions page into a position's detail to get manage mode (tabs: Now, Position, Chart, Adjust, History, Sentiment).

Steps to Test
  1. Navigate to /invest/positions
  2. Click into any active position to open its strategy detail page
  3. Verify you're in manage mode (you should see "Adjust" in the tab bar)
  4. Click the "Adjust" tab
  5. Find and click the "Get AI Recommendations" button
  6. Button should show "Analyzing..." with reduced opacity while loading
  7. After response (3-8 seconds), verify:
    • Urgency indicator pill at top (Immediate / Act soon / Monitor)
    • Market context text in italic
    • One or more adjustment cards (purple-tinted), each showing:
      • Adjustment type badge (e.g., "roll_down", "close_early")
      • Risk level badge (HIGH/MEDIUM/LOW)
      • Description paragraph
      • New legs section with bullet points
Expected API Call (DevTools)
POST /api/adjust // Request body: { "ticker": "AAPL", "strategy": "bull_put_spread", "legs": [...], "dte": 14, "verdictState": "HOLD", "modelMode": "budget-qwq" } // Response: { "adjustments": [ { type, label, description, newLegs, riskLevel } ], "marketContext": "...", "urgency": "monitor" }
Pass Criteria
PASS if: AI adjustment cards render with meaningful, position-specific recommendations. Urgency and risk levels are appropriate for the position state. Adjustment types make sense for the strategy (e.g., "roll" for spreads, "close early" for profitable positions).
Fail Indicators
FAIL if: Button stays on "Analyzing..." forever, no adjustment cards render, adjustments are nonsensical (wrong strategy type), risk levels are all the same, or Network tab shows error on /api/adjust.
Verification Checklist
  • Adjust tab visible in manage mode
  • "Get AI Recommendations" button visible
  • Loading state shows correctly
  • Urgency pill rendered at top
  • Market context text appears
  • Adjustment cards render with type + risk badges
  • Each card has description + new legs
  • Recommendations are position-specific
  • No console errors
