The Quality Mean-Reversion Exception

Why a mega-cap that is oversold above a defended wall is treated as a bounce, not a falling knife — the rules we apply, where they live, and the three bugs fixed to make them fire.

0TL;DR

The engine used to stand aside on strong-downtrend names even when they were extremely oversold. For high-quality mega-caps sitting above a defended support wall, that stand-aside is wrong — those names mean-revert. We added a narrow, guard-railed exception that reinterprets the setup as a bounce and recommends a defined-risk bull call spread.

The one-sentence rule. If a name is a mega-cap, is oversold (RSI<30), sits above a defended put wall (spot > put wall, gamma confidence ≥ 0.45), and the engine would otherwise stand aside or veto as a falling knife — then waive the knife veto and promote the neutral pick to a bull call spread (a debit vertical). If price breaks below the put wall, the exception voids — that is the "real structure change".

1The problem it solves

Three of the engine's signals genuinely conflict on an oversold mega-cap. The old behaviour resolved that conflict by doing nothing.

SignalReadsSays
Gamma regimePositive gamma · mean-revertingRange-bound — income/range trades
TechnicalStrong downtrend (ADX 34) but RSI 12 — extreme oversoldBounce likely; don't chase shorts
IV / SkewIV/RV 0.86 — vol cheap vs realized, backwardatedBuy options / debit structures; poor time to sell

The deterministic engine computes an oversold flag but never lets it move direction — that comes only from SMA alignment, which on a crashed name is "mixed" → trendScore = 0.50 → neutral. So the directional gate can't fire, the neutral pick (a broken-wing butterfly) prices as a debit, and the decision engine correctly rejects it as prices_as_debit. Net result: NO_TRADE on exactly the setup a discretionary trader would take.

The exception does not change the core engine's neutrality. It sits in the reaction gate — the overlay that already knows how to promote a neutral pick to a directional spread or veto a falling knife — and adds one guard-railed branch.

2The decision pipeline

Every recommendation flows through the same deterministic chain. The exception lives at step 3.

1

Core engine — select & score

pipeline/strategy-engine.js · api/pipeline/strategy-engine.cjs
Gamma walls + IV + technicals → a strategy (condor / BWB / directional / calendar / iron-fly) and a 0–100 score. direction is derived from SMA alignment only, so a crashed name is neutral.

2

Reaction gate — compute

shared/reaction/gate.cjs → computeReactionGate()
Runs the S/R zone pipeline + regime classification + mapBias. Produces regime, bias, trendIntoZone, the falling-knife flag — and now qualityBounce.

3

Reaction gate — decide exception here

shared/reaction/gate.cjs → applyReactionGate()
Three outcomes: quality bounce → promote to bull call spread (NEW); falling-knife veto → stand aside; promote a neutral pick to the aligned directional spread; or keep the gamma pick.

4

Leg builder — construct

api/src/tools/leg-builder.ts → buildBullCallSpread()
Buys a call near ATM, sells a call toward the call wall. Fail-closed: legs must pass topology validation (shared/validate.js) or nothing ships.

5

Decision engine — go / no-go

api/src/tools/decision-engine.ts → buildDecision()
Classifies regime, prices the structure, decides APPROVED / WATCHLIST / NO_TRADE. A bull call spread is a debit vertical, so the prices_as_debit rejection does not apply to it.

3The exception rules, precisely

Two functions, both in shared/reaction/gate.cjs — the single implementation all three surfaces share.

3.1 — Computing the flag

qualityBounce is true only when every clause holds. Each clause is an independent guard.

// shared/reaction/gate.cjs → computeReactionGate()
const oversold        = typeof rsi === 'number' && rsi < 30;
const wallDefended    = putWall != null && spot > putWall && (gammaConfidence || 0) >= 0.45;
const standAsideOrKnife =
      (trendIntoZone && trendIntoZoneSide === 'support')  // falling-knife setup
   || biasResult.bias === 'no_trade'                       // engine standing aside
   || regime === 'testing_support';                       // sitting on support

const qualityBounce = !!(isQualityName && oversold && wallDefended && standAsideOrKnife);
ClauseMeaningWhy it's there
isQualityNameTicker's marketCapTier === 'mega'Only durable mega-caps earn the mean-reversion assumption. A small speculative name's oversold dip is a genuine knife.
oversoldRSI < 30The bounce thesis needs an actual extreme to revert from.
wallDefendedspot > put wall AND gamma conf ≥ 0.45The support must be real and unbroken. This is the structural-break guard.
standAsideOrKnifeThe engine would otherwise veto or stand asideWe only override where there is something to override — never manufacture a trade the engine already likes.

3.2 — Acting on the flag

// shared/reaction/gate.cjs → applyReactionGate() — runs BEFORE the knife veto
if (gate.qualityBounce && NEUTRAL_PICKS.has(gammaStrategyCode)) {
  return {
    strategy: 'bull_call_spread', direction: 'bullish',
    testing: !!gate.testingSupport,
    flag: 'quality_mean_reversion',
    note: `quality mean-reversion — mega-cap oversold above a defended support wall; 
           falling-knife veto waived, defined-risk bull call spread`,
  };
}
  • Runs before the veto. Placing it first means the falling-knife flag can never fire for a qualifying name.
  • Neutral picks only. NEUTRAL_PICKS = { iron_butterfly, broken_wing_butterfly, iron_condor }. An already-directional engine pick is never flipped.
  • Debit vertical. The promotion is always a defined-risk structure — max loss is the debit paid. No naked exposure, ever.

Structural-break guard, restated. The exception is a bet that the support has not broken. The moment spot ≤ put wall, wallDefended is false → qualityBounce is false → the knife protection returns, mega-cap or not. This is what stops an Intel-style value trap from sailing through on brand alone.

4Threshold reference

Every tunable number in one place, with the reasoning and the source of truth.

KnobValueRationaleSource

Wall-intact confidence floor≥ 0.45Moderate, not the 0.60 condor "strongly defended" grade — a bounce doesn't need condor-strength walls, and the score is depressed by the wide band the selloff itself creates. Above the analyzer's 0.30 "weak" cutoff, so noisy walls still fail.gate.cjs
Structural-break linespot > put wallBelow the defended wall = real structural change → exception voids.gate.cjs

Two "confidence" numbers — don't confuse them. The Discover UI shows an 86% "walls strongly defended" figure — that is the blended confidence (OI 100% + Volume 100% + Delta 54%). The reaction gate's wallDefended check uses analysis.confidence_score, a different metric — the same one the condor gate needs ≥0.60 for. For ORCL that is 0.551. The 0.45 floor is calibrated against this number, not the 86%.

5Why a bull call spread specifically

The promoted structure is a debit vertical, and that choice is load-bearing for three independent reasons.

Matches the vol read

IV/RV < 1 means options are cheap versus realized movement. A debit spread buys that cheap vol directionally, instead of selling under-priced premium.

Caps the loss

Max loss is the debit paid — the built-in "lose a little and live to re-buy" property. No structural machinery needed; the shape is the risk control.

Sidesteps the debit rejection

The decision engine rejects a credit structure that prices as a debit (prices_as_debit). A bull call spread is not in CREDIT_DEFINED_RISK, so that rejection never applies — which is exactly why the neutral BWB (a credit structure) failed here and the debit vertical passes. decision-engine.ts:211

Leg construction. Buy a call near ATM, sell a call toward the call wall. ORCL: long 141 call / short 152.5 call (the 07-17 expiry snaps the short to the 160 call wall). leg-builder.ts → buildBullCallSpread()

6The three bugs — and how each was fixed

Wiring the rule surfaced three defects. Two were about the feature; the third was a latent build bug the feature merely exposed.

Bug 1 — Mega tags missing for the biggest names DATA

Symptom

Only 12 names carried marketCapTier: mega — and the set excluded META, AAPL, MSFT, NVDA, GOOG, AMZN, TSLA, AVGO, NFLX. The exception would silently never fire for META, the headline example.

Fix

Backfilled those 9 names in pipeline/ and web/scanner/company-metadata.json. Mega set 12 → 21. Root cause: the tier field was populated inconsistently and watchlist.json has no marketCapMapping at all, so getMarketCapData returned null tiers — company-metadata.json is the real source.

Bug 2 — Wall-intact floor set one grade too high THRESHOLD

Symptom

wallDefended required gamma confidence_score ≥ 0.60 (borrowed from the condor "strongly defended" bar). ORCL's score is 0.551 — a real wall ($125, 5,686 put OI, spot 11% above) whose score is dragged down by the wide 19.5% band the selloff created. Exception blocked.

Fix

Lowered the floor to 0.45 — moderate-or-better, above the 0.30 "weak" cutoff. A bounce doesn't need condor-strength walls, and gating on condor-grade penalised the very volatility that produced the oversold setup. Genuinely noisy walls (<0.45) still fail.

Bug 3 — Deployed validator frozen without the debit-vertical rules BUILD · LATENT

Symptom. The promotion fired correctly and the leg builder produced a valid 2-leg bull call spread — but topology validation rejected it with unknown strategy "bull_call_spread", so ai.ts fell back to the BWB gamma pick → back to NO_TRADE.

Root cause. The API build ran cp -r src/shared dist/shared. Once dist/shared exists, that command nests the copy into dist/shared/shared/ instead of overwriting. And tsc never emits validate.js (no allowJs). So dist/shared/validate.js — the file actually loaded at runtime — froze at its first-ever build, missing the bull_call_spread and bear_put_spread VALIDATOR rules that were later added to source.

Blast radius. This predates the quality work and silently broke every promotion to those two debit verticals across all surfaces. The quality exception is simply the first thing that routinely emits bull_call_spread, so it exposed the freeze.

// api/package.json → "build"
- tsc && cp -r src/shared dist/shared && ...
+ tsc && rm -rf dist/shared && cp -r src/shared dist/shared && ...

Verified after the fix: dist/shared/validate.js carries the rules, no nesting, and buildLegs builds a 2-leg bull call spread on the live ORCL chain.

7Worked example — ORCL

Spot $140.85 · RSI 12.4 · ADX 34.3 · IV/RV 0.86 · put wall $125 (5,686 put OI) · call wall $152.5 · gamma confidence 0.551.

Before

NO_TRADE

  • Engine direction = neutral → picks broken-wing butterfly.
  • BWB is a credit structure; on this chain it prices as a net debit.
  • Decision engine: prices_as_debit → stand aside.

After

WATCHLIST · Bull Call Spread

  • qualityBounce = true (mega ✓ · RSI 12.4 ✓ · $140.85 > $125 & conf 0.551 ≥ 0.45 ✓ · bias no_trade ✓).
  • Promoted BWB → bull call spread, flag quality_mean_reversion.
  • Legs: long 141 call / short 152.5 call. Debit vertical → clears the debit rejection.
  • Approaching (not testing) support → APPROVED capped to WATCHLIST.

8Consistency & maintenance

  • One implementation, three surfaces. The rule lives only in shared/reaction/gate.cjs. Discover calls it via reaction-features.ts; the scanner via pipeline/reaction-gate.cjs; movement-range directly. They cannot disagree.
  • Two mega lists, kept in sync by hand. The scanner reads marketCapTier === 'mega' from company-metadata.json; the API mirrors the same 21 names in api/src/tools/quality-names.ts (no metadata file in the Cloud Function). Change one → change the other, or the two surfaces disagree on eligibility.
  • Deploy coupling. API changes need cd api && npm run deploy (Firebase functions) or they stay inert. Pipeline changes need a daemon restart: launchctl kickstart -k gui/$(id -u)/com.newleaf.pipeline.
  • Build hygiene. dist/shared is regenerated from source on every build (now with rm -rf first). Never hand-edit files under dist/ — they are overwritten.

Honesty note. These weights and thresholds are intuition-based, not outcome-validated against real trade P&L. The exception is deliberately confined to defined-risk structures precisely because it is unproven. No accuracy or win-rate claim should attach to it until it is measured against real pick_outcomes.
