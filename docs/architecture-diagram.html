Layer Details

Layer 1: Web React + Vite Node.js server Firebase Hosting

Runtime: Browser (React SPA) + Node.js server (server.cjs for dev, Firebase Hosting for prod)

Build: vite build produces dist/. SSR prerender for 12 routes (SEO). Workbench static HTML copied to dist/workbench/.

Deploy: firebase deploy --only hosting:newleafsystem → newleafsystem.com

Auth: Firebase Auth (Google, email). Admin status checked via Firestore user doc.

Data reads: Firestore client SDK (direct). R2 CDN proxied through server.cjs at /r2/reports/*.

Does NOT: Write to tiles/analyses/weeklyPicks. Make LLM calls. Run scheduled jobs.

Layer 2: API TypeScript + Fastify Firebase Cloud Functions v2

Runtime: Node.js 20. Fastify HTTP framework. Dev: tsx watch at localhost:5400. Prod: Firebase Cloud Functions (us-central1), 1GB RAM, 540s timeout.

Deploy: npm run build && firebase deploy --only functions → cloudfunctions.net/api

LLM Router: Single class (LLMRouter) dispatching to 10 model tiers across 6 providers. Token counting + cost tracking on every call. Model assignments configurable via env vars.

Tools: Alpaca client (spot, chains, bars), technical indicators (via shared/indicators), 4-engine sentiment, gamma wall analysis (Nasdaq OI), Serper search.

Auth: API key in X-API-Key header. RBAC tiers: free < basic < premium < admin. Dev mode accepts DEV_API_KEY.

Secrets: Firebase Secret Manager in prod. .env / .env.local in dev.

Layer 3: GenerateRecommendations Node.js CommonJS Python (PDFs)

Runtime: Node.js 20 (CommonJS scripts). Python 3.10 for PDF generation (WeasyPrint). Runs locally on developer machine or scheduled via pipeline.

NOT deployed to cloud. Runs on local machine or a dedicated VM. Calls api/ over HTTP for all LLM, sentiment, and indicator needs.

Sole writer to Firestore tiles, analyses, weeklyPicks collections. All writes carry 8 provenance fields.

Key scripts: publish-pick.cjs (single pick), analyse-tiles.cjs (batch), process-wip-picks.cjs (WIP flow), generate-outputs.js (PDFs + archives), create-weekly-picks.js (bundle), close-week.js (P&L), send-weekly-email.js.

HTTP dependencies: api/ (LLM, sentiment, indicators), Alpaca (spot, chain), R2 CDN (gamma walls).

Layer 4: Pipeline Node.js Python Flask

Runtime: Node.js (schedulers, data pipeline) + Python Flask (Yahoo OI service at port 5300). Always-on via macOS LaunchAgent.

Yahoo OI Service: yahoo-svc/option_api.py — Flask app serving Open Interest data from yfinance. The only real OI source. Port 5300.

Schedulers: node-cron in index.js — 15-min fast scan, OI enrichment, daily catchup, health checks.

Uploads to: Cloudflare R2 (reports, snapshots, pipeline status, manifests).

Status: LaunchAgent still points at legacy /Users/manish/dev/newleaf-pipeline/. Cutover to monorepo pending.

Communication Patterns

Who calls whom

  web/ ──────── reads ────────→ Firestore (tiles, analyses, weeklyPicks, users)
  web/ ──────── reads ────────→ R2 CDN (gamma walls, reports, PDFs)
  web/ ──────── HTTP ─────────→ api/ (AI features, indicators, sentiment)

  api/ ──────── SDK ──────────→ Anthropic, OpenAI, xAI, Google, DeepSeek, DashScope
  api/ ──────── REST ─────────→ Alpaca (market data)
  api/ ──────── REST ─────────→ Reddit, StockTwits, Serper
  api/ ──────── import ───────→ shared/indicators/ (pure math)

  genrecs/ ──── HTTP ─────────→ api/ (LLM calls, sentiment, indicators)
  genrecs/ ──── REST ─────────→ Alpaca (spot, chain — direct, not via api/)
  genrecs/ ──── REST ─────────→ R2 CDN (gamma walls)
  genrecs/ ──── writes ───────→ Firestore (tiles, analyses, weeklyPicks)
  genrecs/ ──── uploads ──────→ R2 (PDFs, via upload-to-r2.py)

  pipeline/ ─── REST ─────────→ Yahoo Finance (via yahoo-svc Python)
  pipeline/ ─── uploads ──────→ R2 (reports, manifests, pipeline status)
  pipeline/ ─── writes ───────→ Firestore (marketState)
