Layer Details

Layer 1: Web React + Vite Node.js server Firebase Hosting

Runtime: Browser (React SPA) + Node.js server (server.cjs for dev, Firebase Hosting for prod)

Build: vite build produces dist/. SSR prerender for 12 routes (SEO). Workbench static HTML copied to dist/workbench/.

Deploy: firebase deploy --only hosting:newleafsystem → newleafsystem.com

Auth: Firebase Auth (Google, email). Admin status checked via Firestore user doc.

Data reads: Firestore client SDK (direct). R2 CDN proxied through server.cjs at /r2/reports/*.

Does NOT: Write to tiles/analyses/weeklyPicks. Make LLM calls. Run scheduled jobs.

Layer 2: API TypeScript + Fastify Firebase Cloud Functions v2

Runtime: Node.js 20. Fastify HTTP framework. Dev: tsx watch at localhost:5400. Prod: Firebase Cloud Functions (us-central1), 1GB RAM, 540s timeout.

Deploy: npm run build && firebase deploy --only functions → cloudfunctions.net/api

LLM Router: Single class (LLMRouter) dispatching to 10 model tiers across 6 providers. Token counting + cost tracking on every call.

Tools: Alpaca client (spot, chains, bars), technical indicators (via shared/indicators), 4-engine sentiment, gamma wall analysis, Serper search.

Auth: API key in X-API-Key header. RBAC tiers: free < basic < premium < admin.

Layer 3: GenerateRecommendations Node.js CJS Python (PDFs)

Runtime: Node.js 20 (CommonJS scripts). Python 3.10 for PDF generation (WeasyPrint). Runs locally.

NOT deployed to cloud. Calls api/ over HTTP for all LLM, sentiment, and indicator needs.

Sole writer to Firestore tiles, analyses, weeklyPicks. All writes carry 8 provenance fields.

Key scripts: publish-pick.cjs, analyse-tiles.cjs, process-wip-picks.cjs, generate-outputs.js, create-weekly-picks.js, close-week.js, send-weekly-email.js.

Layer 4: Pipeline Node.js Python Flask Cloud RunNEW

Scheduler: Node.js node-cron in index.js. macOS LaunchAgent. 15-min fast scan, OI enrichment, daily catchup.

Yahoo OI Service: Python Flask app providing real Open Interest data from yfinance.

Two deployment modes:

• Local: python3 option_api.py at localhost:5300 (dev, low latency)

• Cloud Run: https://yahoo-options-svc-m2cty2vxuq-uc.a.run.app (production, always-on, no local dependency)

Uploads to: Cloudflare R2 (reports, snapshots, manifests, pipeline status).

Access URLs

EnvironmentURLNotes
Production (Cloud Run) https://yahoo-options-svc-m2cty2vxuq-uc.a.run.app Always-on, auto-scaling, no local dependency. GCP us-central1.
Development (local) http://localhost:5300 Run cd pipeline/yahoo-svc && python3 option_api.py

Why two modes?

Cloud Run deployment means the pipeline scheduler, genrecs scripts, and even api/ can access real Open Interest data without needing a local Python process running. Yahoo Finance blocks direct Node.js calls — this Python wrapper (Flask + yfinance) is the only OI data source in the ecosystem.

Local mode is faster for development and avoids Cloud Run cold starts (~2-5 seconds).

Data provided

  • Real Open Interest per strike (calls + puts) — not available from Alpaca
  • Volume per strike
  • Calculated Greeks (delta, gamma, theta, vega) via Black-Scholes
  • Bid/ask/last/mid prices
  • Implied volatility per contract
  • Available expiration dates for any symbol

Communication Patterns

  web/ ──────── reads ────────→ Firestore (tiles, analyses, weeklyPicks, users)
  web/ ──────── reads ────────→ R2 CDN (gamma walls, reports, PDFs)
  web/ ──────── HTTP ─────────→ api/ (AI features, indicators, sentiment)

  api/ ──────── SDK ──────────→ Anthropic, OpenAI, xAI, Google, DeepSeek, DashScope
  api/ ──────── REST ─────────→ Alpaca (market data)
  api/ ──────── REST ─────────→ Yahoo OI (Cloud Run or localhost:5300)
  api/ ──────── REST ─────────→ Reddit, StockTwits, Serper
  api/ ──────── import ───────→ shared/indicators/ (pure math)

  genrecs/ ──── HTTP ─────────→ api/ (LLM calls, sentiment, indicators)
  genrecs/ ──── REST ─────────→ Alpaca (spot, chain — direct)
  genrecs/ ──── REST ─────────→ R2 CDN (gamma walls)
  genrecs/ ──── writes ───────→ Firestore (tiles, analyses, weeklyPicks)
  genrecs/ ──── uploads ──────→ R2 (PDFs, via upload-to-r2.py)

  pipeline/ ─── REST ─────────→ Yahoo OI (Cloud Run or localhost:5300)
  pipeline/ ─── uploads ──────→ R2 (reports, manifests, pipeline status)
  pipeline/ ─── writes ───────→ Firestore (marketState)
