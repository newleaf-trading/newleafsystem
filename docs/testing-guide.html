Test 1: Technical Indicators (MACD verification)

What to verify

The /api/indicators/:ticker endpoint returns real computed MACD, RSI, Bollinger, and SMA values that match a charting tool (TradingView, Yahoo Finance).

1

Call the indicators endpoint

curl -s http://localhost:5400/api/indicators/AAPL | python3 -m json.tool
2

Check the response includes MACD fields

# Expected fields in response.indicators:
{
  "price": 198.50,
  "sma20": 195.30,
  "sma50": 191.80,
  "sma100": 188.40,
  "sma200": 185.20,
  "rsi14": 55.3,
  "bollingerUpper": 202.10,
  "bollingerLower": 188.50,
  "bollingerWidth": 6.97,
  "adx14": 22.5,
  "atr14": 3.45,
  "macdLine": 1.234,      ← NEW (F1)
  "macdSignal": 0.987,    ← NEW (F1)
  "macdHistogram": 0.247, ← NEW (F1)
  "priceVsSma": "above_all",
  "smaTrend": "bullish"
}
3

Cross-check against TradingView

Open TradingView for the same ticker. Compare:

FieldAPI valueTradingViewTolerance
RSI(14)from APIfrom chart+-2 (Cutler's vs Wilder's variant)
MACD linefrom APIfrom chart+-0.5 (different EMA seeds)
SMA20from APIfrom chartShould match exactly

Run unit tests

node /Users/manish/newleafsystem/shared/indicators/index.test.js

Note on RSI variance: Our RSI uses Cutler's variant (simple average) while TradingView uses Wilder's (exponential smoothed). Values may differ by 1-3 points. This is documented and intentional.

Test 2: Sentiment (4-engine unified)

What to verify

The /api/sentiment/:ticker endpoint runs all 4 engines (Claude, Grok, Gemini, Reddit) through the LLM router and returns a weighted composite.

1

Call the sentiment endpoint

curl -s http://localhost:5400/api/sentiment/NVDA | python3 -m json.tool

This takes 30-60 seconds (4 parallel LLM calls).

2

Verify all 4 engines reported

# Check response.engines has all 4:
"engines": {
  "claude": { "score": 62, "label": "neutral", ... },
  "grok":   { "score": 71, "label": "bullish", ... },
  "gemini": { "score": 58, "label": "neutral", ... },
  "reddit": { "score": 75, "label": "bullish", ... }
}

# Check response.activeEngines === 4
# Check response.source === "claude+grok+gemini+reddit"
3

Verify cost tracking

# Response includes cost object:
"cost": {
  "totalCost": 0.0234,
  "totalInputTokens": 4500,
  "totalOutputTokens": 1200,
  "calls": [
    { "model": "claude-haiku", ... },
    { "model": "grok", ... },
    { "model": "gemini-flash", ... }
  ]
}
4

Verify weights

Composite score should equal: Claude*0.30 + Grok*0.25 + Gemini*0.25 + Reddit*0.20 (normalized if any engine failed).

If an engine fails: The response will still succeed with fewer engines. Check activeEngines count. If all 4 fail, API returns 502.

Test 7: Ground Truth Indicator Validation

What to verify

When the LLM tries to substitute its own indicator numbers instead of echoing the ground truth, the validation catches it and fails the analysis.

1

After a successful pick creation, compare

# Get indicators from API
curl -s http://localhost:5400/api/indicators/AAPL | python3 -c "
import json, sys
d = json.load(sys.stdin)['indicators']
print(f\"API RSI: {d['rsi14']}\")
print(f\"API MACD: {d['macdLine']}\")
print(f\"API SMA20: {d['sma20']}\")
"

# Get indicators from the published analysis
cat output/2026-W21/enriched/AAPL-iron-condor.json | python3 -c "
import json, sys
d = json.load(sys.stdin)['analysis']['technicalIndicators']
print(f\"Analysis RSI: {d['rsi']['value']}\")
print(f\"Analysis MACD: {d['macd']['macdLine']}\")
print(f\"Analysis SMA20: {d['movingAverages']['sma20']}\")
"

Values should match within tolerances: RSI +-0.5, prices +-1%, MACD +-0.001.

2

If validation fails

The script will show an error like:

Indicator validation failed — LLM substituted values:
  rsi.value: expected 55.3, got 48.2 (tolerance 0.5)
  macd.macdLine: expected 1.234, got 2.100 (tolerance 0.001)

The pick will NOT be published. This is correct behavior — fail loud, publish fewer accurate picks.
