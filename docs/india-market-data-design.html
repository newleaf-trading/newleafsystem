Indian Market Data Integration

Design doc — what APIs & data NewLeaf needs to support Indian (NSE/BSE) stocks & options, and whether Zerodha + Groww are enough.

Status: Proposal Author: NewLeaf Date: 2026-06-20 Scope: data layer + structural assumptions
TL;DR

Zerodha (Kite Connect) or Groww covers ~70% — the live/historical price + option-chain + open-interest layer. Neither is sufficient alone. You still need to (a) compute Greeks/IV yourself, (b) source an earnings / corporate-actions calendar elsewhere, (c) replace US-only sentiment sources, and (d) rewrite structural assumptions: lot sizes, expiries, symbol format, and the gamma model. If this is a multi-user product, broker APIs likely violate redistribution ToS — use a licensed data vendor instead.

3. Are Zerodha + Groww enough?

For the market-data spine (price + chain + OI): yes. For the full product as it stands today: no. They are broker APIs designed to trade your own account — not market-data platforms. Three data categories have zero broker coverage, and several deep structural assumptions break.

⚠ Redistribution / ToS risk (the decisive factor)

Broker APIs are account-tied and intended for the account holder's own trading. Using one as a backend data feed serving other users can violate the terms and exchange data-licensing rules. If NewLeaf-India is a multi-user product, this alone pushes you off broker APIs and onto a licensed data vendor.

4. The three gaps brokers don't cover

Gap 1 — Greeks & IV engine

Compute via Black-Scholes from spot + strike + DTE + risk-free rate + dividend yield. Use the Indian risk-free rate (~6.5–7% T-bill / MIBOR), not US rates. NSE also publishes per-contract IV in its own option chain if you prefer to read rather than compute. We already have BS estimation as a fallback — this just promotes it to the primary path.

Gap 2 — Earnings / corporate-actions calendar

No broker provides this. Options: scrape NSE corporate-announcements + board-meeting (earnings) feed (fragile — cookies/rate-limits), or a fundamentals vendor with India coverage (Trendlyne, Tickertape, Screener.in — none have a clean official API; FMP / Alpha Vantage India coverage is spotty).

Gap 3 — Sentiment

Our Serper / Reddit / LLM stack mostly ports, but swap the India-irrelevant pieces: drop StockTwits, repoint Reddit at r/IndianStreetBets / r/IndiaInvestments, and lean on X/Twitter + Telegram + Moneycontrol for retail flow.

5. Structural rewrites India forces

These break code, not just data sources — they're the real cost of the port.

Assumption (US)India realityImpact
Wide options universe (232-symbol watchlist) Only ~180–220 SEBI-approved F&O stocks have options, plus indices (NIFTY, BANKNIFTY, FINNIFTY, MIDCPNIFTY, SENSEX). Most liquidity is in index options. Equity strategies work broadly; option strategies restricted to the F&O list. Watchlist needs an F&O-eligibility flag.
100-share contracts Options trade in lots. Lot sizes change periodically (SEBI keeps notional ₹5–10 lakh) — e.g. NIFTY moved to 65, BankNifty 30 for the Jan-2026 series. Per-100-share premium / max-loss / sizing math (legMath.js) is wrong. Lot size must come from the instruments master, not a constant.
Weekly expiries everywhere SEBI's 2024 rule collapsed weeklies to one benchmark index per exchange. BankNifty weeklies gone; stock options monthly only. Weekly-theta-decay strategies lose most of their universe. Expiry calendar logic must be exchange-rule-aware.
OCC symbol format (AAPL240719C00150000) NSE tradingsymbols (e.g. NIFTY26JAN24000CE) + Kite instrument tokens. Full rewrite of the OCC parser (alpaca.ts:92) and any symbol-format assumptions downstream.
Gamma-wall (GEX) model Dealer-positioning concept is US-centric. Indian OI is retail/prop-dominated & exchange-reported. Local equivalents: Max Pain, PCR, OI-based S/R. The math (γ × OI × spot) ports, but the interpretation doesn't. Reframe the narrative + add Max Pain / PCR.
US market hours / ET IST, 09:15–15:30. Different holiday calendar. Scheduler / cron times, "EOD" snapshot windows, calendar feeds all shift to IST.

Recommendation
  • Own account / single-user: start with Kite Connect for price + chain + OI, add our BS engine for Greeks/IV, bolt on an events + sentiment source. Groww (₹499/mo, claims Greeks) is a viable cheaper alternative.
  • Product for other users: don't build on a broker feed — use a licensed vendor (TrueData / GDFL) or an analytics API (Sensibull / Quantsapp) to avoid the ToS problem and get Greeks/IV/Max-Pain precomputed.

7. Target architecture (adapter layer)

8. Phasing & open questions

Suggested phasing

  1. Phase 0 — Decide deployment model. Single-user vs multi-user determines broker-API vs licensed-vendor. Blocks everything.
  2. Phase 1 — Data spine. Kite/Groww adapter: quotes, bars, chain, OI for indices + a handful of F&O stocks. Symbol map + lot-size table from instruments master.
  3. Phase 2 — Greeks/IV engine. Promote BS to primary; wire Indian risk-free rate + dividend yield. Validate against NSE-published IV.
  4. Phase 3 — Events + sentiment. Earnings/ex-div feed; repoint sentiment sources to Indian platforms.
  5. Phase 4 — Analytics reframe. Add Max Pain / PCR; reframe gamma narrative; fix expiry/lot UI.

Open questions

  • Single-user or multi-user product? (Determines ToS-legal data source.)
  • Index-options-first, or do we need single-stock F&O from day one?
  • Compute Greeks ourselves, or buy a vendor that precomputes them (Sensibull/Quantsapp)?
  • Is the US system staying live in parallel (region toggle) or is this a fork?
  • Budget tolerance: free broker API (with ToS risk) vs paid licensed vendor.
Note on volatile facts

Lot sizes, weekly-options rules, and broker API pricing change frequently (SEBI revises lot sizes periodically; the Jan-2026 series moved NIFTY to 65 / BankNifty to 30). Treat all specific numbers here as "verify at build time," and always read lot size + expiry rules from the live instruments master rather than hardcoding.
