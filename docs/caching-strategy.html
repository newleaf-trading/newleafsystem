6 Cache Layers — What We Cache

1. Indicators

CACHED
EndpointGET /api/indicators/:ticker
TTL5 minutes
KeyTicker symbol (e.g. AAPL)
WhatRSI, MACD, Bollinger, SMA 20/50/100/200, ADX, ATR
Why cacheableComputed from 250 daily bars. Bars don't change intraday. Recomputing every request wastes ~800ms + 2 Alpaca calls.
Saving/hit~800ms latency + 2 API calls
Max entries50

2. AI Market Read

CACHED
EndpointPOST /api/ai-read
TTL5 minutes
KeyTicker symbol
WhatOne-sentence market synthesis from LLM
Why cacheableSame ticker at the same time has the same indicators (RSI/ADX/trend are daily). The LLM would produce the same sentence.
Saving/hit$0.003 + ~3s (1 LLM call: QwQ)
Max entries50

3. Strategy Ranking

CACHED
EndpointPOST /api/recommend
TTL10 minutes
Key{ticker}:{expiry}
What3 ranked strategies with scores, legs, rationale
Why cacheableSame ticker + expiry = same chain = same ranking. The option chain doesn't shift meaningfully in 10 minutes during normal hours.
Saving/hit$0.01 + ~5s (1 LLM call + 4 API calls)
Max entries30

4. Sentiment

CACHED
EndpointGET /api/sentiment/:ticker
TTL30 minutes
KeyTicker symbol
What4-engine composite (Claude + Grok + Gemini + Reddit)
Why cacheableNews and social sentiment don't change meaningfully in 30 minutes. This is the most expensive cached endpoint — 4 parallel LLM calls.
Saving/hit$0.01–0.03 + ~30s (4 LLM calls)
Max entries30

5. Verify (Biggest Win)

CACHED
EndpointPOST /verify
TTL30 minutes
KeySHA256 of {ticker + sorted legs + modelMode}
WhatFull 8-agent verdict, evidence, debate, risk report, mutations
Why cacheableSame trade legs = same verdict. Re-verifying an unchanged trade should NOT burn a daily credit or cost $0.05.
Saving/hit$0.05 + ~24s + 1 daily credit (8 LLM calls)
Max entries20

6. Gamma Analysis

CACHED ×2
EndpointGET /api/gamma-analysis/:ticker/:expiry
TTL60 minutes (API) + 60 minutes (Yahoo OI Service)
Key{ticker}:{expiry}
WhatGEX walls, ATM IV, confidence scores, top gamma strikes
Why cacheableOI updates once daily after market close (~5:30 PM ET). During trading hours, OI is yesterday's number. Double-cached: API level + Yahoo OI Service level.
Saving/hit~2s (Yahoo API call avoided)
Max entries50 (API) + 200 (Yahoo OI Service)

Request Flow: Cache Hit vs Miss

First Request (Cold — All Miss)

1. /api/snapshot/AAPL → Alpaca NO CACHE ~500ms
2. /api/indicators/AAPL → Alpaca bars → compute MISS ~800ms → cached 5 min
3. /api/gamma-analysis/AAPL/2026-06-12 → Yahoo OI MISS ~2s → cached 60 min
4. /api/ai-read → QwQ LLM MISS ~3s → cached 5 min
5. /api/recommend → Claude LLM MISS ~5s → cached 10 min
6. /verify → 8-agent pipeline MISS ~24s → cached 30 min
Total: ~35s, ~$0.07, 14 LLM calls

Second Request (Warm — All Hit)

1. /api/snapshot/AAPL → Alpaca NO CACHE ~500ms
2. /api/indicators/AAPL → CACHE HIT ~1ms
3. /api/gamma-analysis/AAPL/2026-06-12 → CACHE HIT ~1ms
4. /api/ai-read → CACHE HIT ~1ms
5. /api/recommend → CACHE HIT ~1ms
6. /verify → CACHE HIT ~1ms
Total: ~500ms, $0.00, 0 LLM calls

Cache Invalidation

TriggerWhat Happens
TTL expiresEntry removed on next access. Next request is a cache miss → fresh data fetched and cached.
Max entries reachedOldest 20% pruned automatically.
Container restartAll in-memory caches cleared (Cloud Functions cold start). This happens naturally during deployments and scale-down.
Manual clear (future)Planned: POST /admin/cache-clear endpoint for forced invalidation during market-moving events.

When NOT to rely on cache

  • FOMC announcements — sentiment shifts instantly, 30-min cache serves stale data
  • Earnings releases — IV crush happens in minutes, gamma walls shift
  • Flash crashes — spot price stale in 30s cache
  • Future: add event-aware cache that shortens TTL during known events
