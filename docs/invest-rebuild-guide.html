NewLeaf Invest Rebuild

Architecture decisions, what changed, and how to publish tiles — May 2026

Contents 1. What we built 2. Why — the problems it fixed 3. Architecture 4. Data flow: signal → tile → screen 5. How to publish tiles 6. Freshness & centeredness 7. Tiered confidence model 8. Key files

1. What We Built

A complete rebuild of the Invest surfaces — Dashboard, Discover, Positions, Performance, Build, and two detail views (Defend + Decide) — unified around one principle:

Total-dollar P&L is the single stored truth. Every other number is a pure derivation of it. No surface computes P&L independently. Per-contract is always total / qty, never the reverse.

The rebuild also separated scanner signals (unpriced screen output from the pipeline) from priced tiles (real, tradeable candidates with live option chain pricing), introduced freshness classification (so stale candidates are flagged, not presented as live), and added a tiered confidence model (so adversarially-reviewed tiles are visually distinguished from PoP-only tiles).

2. Why — The Problems It Fixed

P&L inconsistency

The same position showed different P&L on different screens. maxProfit/maxLoss were per-contract in some paths, total in others. One view multiplied per-contract by qty; another divided total by qty. The result: a -628% loss display on a profitable trade.

Fix: derivePosition() is the single derivation point. Every surface imports it. No surface recomputes.

3,489 unpriceable tiles polluting Discover

The pipeline scanner wrote ~111 signal docs per day to the tiles collection — with no legs, no premiums, no breakevens. Discover rendered them as tradeable candidates with placeholder numbers ($500 / $500 / 50% / 1.00×).

Fix: Scanner writes to scanner_signals (separate collection). Only priced tiles reach tiles. A read-time priced gate filters any that leak through.

Stale candidates shown as live

An ADBE iron condor with a profit zone of $217–$242 was shown with spot at $261 — already past the upper breakeven — but still said "70% probability" and "Take this trade."

Fix: deriveCandidate() classifies every candidate as fresh, drifted, breached, or expired. Breached/expired tiles are hidden from Discover. Drifted tiles show a warning banner.

Generic confidence field carrying three different signals

The confidence field was set from PoP (publish-pick), adversarial verdict (discover-publish), or gamma wall reliability (strategy-builder) — three conceptually different measures on one field.

Fix: Three named fields: verdictConfidence, wallConfidence, oddsOfProfit. One shared publish gate. No generic confidence written.

Scanner signals (unpriced)

Written by pipeline/sync-r2-to-firestore-fixed.mjs to scanner_signals collection. ~111 per day. Has symbol, strategy name, score, gamma data — no legs, no premiums, no P&L. Source: pipeline-scanner.

Priced tiles (tradeable)

Written to tiles collection by one of four paths (see §5). Has real legs with premiums from a live option chain, computed maxProfit/maxLoss, breakevens, and PoP. Must pass validateTile + applyPublishGate.

5. How to Publish Tiles

There are four ways to publish a priced tile to Discover. All four share one pricing engine and one validation path.

Option A: publish-pick CLI (recommended for manual picks)

cd generaterecommendations

# Dry run first — shows the tile without writing
node publish-pick.cjs AAPL --strategy "iron condor" --expiry 2026-07-18 --dry-run

# Publish live
node publish-pick.cjs AAPL --strategy "iron condor" --expiry 2026-07-18

# Supported strategies:
#   "iron condor"    — neutral, 4-leg
#   "iron butterfly" — neutral, 4-leg (ATM)
#   "bull put"       — bullish, 2-leg
#   "bear call"      — bearish, 2-leg

What it does:

  1. Fetches live spot from Alpaca
  2. Fetches live option chain (requires market hours)
  3. Fetches gamma walls from R2
  4. Builds the strategy (strike selection, P&L, greeks, breakevens, PoP)
  5. Validates: ≥2 legs, premiums non-zero, maxProfit/maxLoss > 0, expiry present
  6. Applies publish gate: PoP ≥ 65% (no verdict on this path)
  7. Writes to tiles/{tileId}
  8. Fetches sentiment (optional, non-fatal on failure)
  9. Runs LLM analysis for deep rationale
  10. Writes to analyses/{tileId} and weeklyPicks/{weekId}
Market hours required. Alpaca returns empty option chains after hours. If you see "0 calls, 0 puts loaded", wait for market open or use a different data source.

Option B: Discover Workbench (browser-based, with verification)

The workbench/discover.html page runs a 5-step flow: scan → build → verify → review → publish. The verification step runs an 8-agent adversarial pipeline (4 analysts + bull/bear debate + risk manager + judge). Tiles published this way carry verdictConfidence and show the "✓ Reviewed" badge.

Endpoint: POST /api/publish-from-analysis (in api/src/routes/publish.ts)

Option C: Strategy Builder (browser-based, manual)

The workbench/strategy-builder.html page lets you manually select strikes from a live chain and publish directly. No adversarial verification — tiles are priced tier, not verified.

Option D: Daily Funnel (automated)

# Runs daily at 10:00am ET via pipeline/index.js
node generaterecommendations/funnel-price.cjs

# Or with options:
node funnel-price.cjs --dry-run       # rank + price, don't write
node funnel-price.cjs --n 20          # override target count (default 15)

What the funnel does:

  1. Reads active scanner_signals
  2. Ranks by opportunityScore × gammaConfidence
  3. Filters: priceable strategies only, confidence ≥ 0.3, dedupes by symbol+strategy
  4. Selects top 2N buffer (prices more than needed)
  5. Prices each off the live Alpaca chain (same builders as publish-pick)
  6. Applies publish gate: PoP ≥ 65%
  7. Quality-selects best N by R:R × 60 + PoP × 40
  8. Deactivates prior source: 'funnel-priced' tiles (scoped — never touches manual tiles)
  9. Writes fresh set to tiles

6. Freshness & Centeredness

Every candidate on Discover is classified by deriveCandidate():

StateMeaningBadgeAction
FreshSpot inside profit zone, within center bandGreen rail"Take this trade" enabled
DriftedSpot near edge or moved ≥2% since structuringAmber rail + banner"Take this trade" + caveat
BreachedSpot outside breakevensHidden from Discover"Re-generate" only
ExpiredDTE ≤ 0Hidden from DiscoverCannot trade

Centeredness is computed from the midpoint of the short strikes (the design center of the max-profit plateau), not from spot-at-generation. Discover sorts by centeredness — most-centered first.

Ideal entry stat

Each candidate detail page shows: "Best near $132.00 · spot $133.31 (centered)" or "4% toward calls". The payoff chart shows a green dashed "Center" line at the ideal entry point.

7. Tiered Confidence Model

Three named fields replace the old generic confidence:

FieldSourceScaleGate input?
oddsOfProfitBlack-Scholes PoP from calcPoP0–100Yes (≥ 65 when no verdict)
verdictConfidence8-agent adversarial pipeline judge0–100 or nullYes (≥ 65 overrides PoP; < 65 rejects)
wallConfidenceGamma wall OI analysis0–1No (informational)

Publish gate logic

// applyPublishGate(tile)
if (verdictConfidence != null) {
  if (verdictConfidence >= 65) → PASS (verified tier)
  else                         → REJECT (adversary flagged it)
} else {
  if (oddsOfProfit >= 65)      → PASS (priced tier)
  else                         → REJECT (PoP below floor)
}

Tier derivation (read-time, never stored)

TierConditionBadge
✓ ReviewedverdictConfidence ≥ 65Shows on Discover + DecidePage with confidence score
(no badge)Everything elseStandard priced tile — no additional badge
