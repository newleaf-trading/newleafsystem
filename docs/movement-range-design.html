Movement & Range — Design Document

How the page works end-to-end: data sources, pipeline dependencies, zone clustering, scoring algorithms, strategy selection, and the funnel that turns 111 symbols into a shortlist.

1. Architecture Overview

Pipeline (runs on Mac Mini) R2 CDN (Cloudflare) Browser (workbench page) ────────────────────────── ────────────────────── ──────────────────────── Alpaca API (prices, IV, Greeks) → reports/{SYM}/latest.json → movement-range.html Nasdaq/Yahoo (Open Interest) → ↑ (uploaded per symbol) ↑ loads 111 reports Strategy Engine (scores, gamma) → ↑ ↑ runs shared/reaction/ ↑ via reaction.browser.js Yahoo Cloud Fn (yfinance) → event-calendar.json → ↑ earnings + ex-div FMP API (dividends supplement) → ↑ ↑

The page is 100% client-side. All analytics run in the browser using shared/reaction/ (the same CJS modules used server-side, compiled into reaction.browser.js). No API calls are made from the page — it reads pre-computed reports from R2.

3. Level Gathering & Zone Clustering

3a. Raw Level Sources

For each symbol, the engine gathers up to 9 raw price levels:

LevelSourceType
Gamma put wallgammaData.analysis.put_wallStatic
Gamma call wallgammaData.analysis.call_wallStatic
SMA 50technicalData.sma50Dynamic
SMA 100technicalData.sma100Dynamic
SMA 200technicalData.sma200Dynamic
Bollinger lowertechnicalData.bb.lowerDynamic (excluded if spot < BB lower)
Bollinger uppertechnicalData.bb.upperDynamic (excluded if spot > BB upper)
20-day swing lowMin of last 20 bar lowsStatic
20-day swing highMax of last 20 bar highsStatic

Levels below spot → support. Levels above spot → resistance. Levels >15% from spot are filtered out.

3b. ATR-Based Zone Merging

Levels within 0.6 × ATR(14) × spot of each other merge into one zone. The zone retains all source labels and pools touches across merged levels.

// Example: AVGO spot $1,412
// ATR = 2.1% → merge threshold = 0.6 × 0.021 × 1412 = $17.79

Put wall $1,380  ─┐
SMA50   $1,386   ─┼─ merge → zone $1,378–$1,391  SUPPORT
20d low $1,389   ─┘           (3 sources, touches pooled)

Call wall $1,460 ─┐
BB upper  $1,463 ─┴─ merge → zone $1,455–$1,468  RESISTANCE

3c. Touch Detection Width

A candle "touches" a zone if it enters the zone's touch band: zone edges ± 0.25 × ATR(14) × spot.

Consecutive bars inside the same zone count as one touch event (dedup).

Module: shared/reaction/zones.cjs

clusterLevels(spot, levels, atrPct) → { supportZones[], resistanceZones[] }

gatherLevels(spot, opts) → raw levels from report data

nearestScoreableZones(spot, sStats, rStats) → closest tested zone pair for S and R

4. Touch/Hold Analysis & Wilson Smoothing

4a. Touch Classification

For each touch event on a zone, the engine classifies the outcome within a 5-bar window:

Zone typeOutcomeCondition
SupportHoldClose recovers +3% from touch close within 5 bars
BreakClose falls >1% below zone bottom for 2+ consecutive bars
Fake breakTrades below zone intraday but closes back inside within 2 bars
PendingTouch on one of the last 5 bars — window not yet complete
ResistanceRejectClose falls −3% from touch close within 5 bars
BreakoutClose rises >1% above zone top for 2+ consecutive bars
Fake breakoutTrades above zone intraday but closes back inside within 2 bars
PendingTouch on last 5 bars — unresolved

4b. Wilson Score Smoothing

Raw rates (e.g. 6/7 = 86%) overstate confidence on small samples. The engine uses the Wilson score interval centre to smooth rates:

// Wilson score interval (z = 1.96 for 95% CI)
centre = (p + z²/2n) / (1 + z²/n)
margin = (z / (1+z²/n)) × sqrt(p(1-p)/n + z²/4n²)

// Examples:
1/1   → smoothed ~60%  (single observation heavily penalized)
6/7   → smoothed ~73%  (close to raw 86% but conservative)
14/20 → smoothed ~68%  (close to raw 70%)

4c. Minimum Touch Gate (n ≥ 3)

Zones with fewer than 3 touches are flagged untested: score = 0, excluded from all scoring and strategy selection. This prevents "100% bounce rate" from a single observation.

Module: shared/reaction/stats.cjs

analyzeZone(candles, zone, type) → { touchCount, holdCount, smoothedRate, ciLow, ciHigh, score, untested, pendingCount }

5. Zone Score (S/R Score)

Each zone gets a 0–100 score based on its historical reaction quality:

ComponentWeightMeasures
Smoothed hold/reject rate30%Wilson-smoothed rate of successful reactions
Touch count (reliability)15%More touches = more reliable signal (caps at 10)
Low failure rate15%Fewer breaks/breakouts = stronger level
Volume confirmation10%% of touches where volume > 20-day average
Gamma wall alignment5%Bonus if gamma wall is within 2% of the zone
Multi-source bonus5%Bonus if the zone merged 2+ distinct level sources

The zone score is displayed as the S/R Score column in the table (S = nearest support zone score, R = nearest resistance zone score). Zones with < 3 touches show "n<3" instead of a score.

Module: shared/reaction/stats.cjs → computeZoneScore()

6. Regime Classification

Each symbol gets a deterministic regime label. The classifier runs in strict precedence order:

#RegimeCondition
1breakout_up / breakout_downSpot closed beyond a scoreable zone's touch boundary
2trendingADX > 25 (checked BEFORE proximity — falling-knife protection)
3testing_support / testing_resistanceSpot within 0.5 × ATR of a scoreable zone
4range_boundContainment > 70% over 45 bars AND ADX < 20 AND both rails scoreable
5unclearNone of the above (confidence capped at 40)

6a. Trend-Into-Zone Detection

When regime = trending AND price is moving TOWARD a nearby zone (downtrend into support, or uptrend into resistance), the trendIntoZone flag is set. This drives the no_trade decision in bias mapping — selling premium into a trend is dangerous.

6b. Containment

Computed against the merged zone band: from nearest support zone's touchLo to nearest resistance zone's touchHi. Each bar in the lookback window that stays fully inside this band counts as "contained."

Module: shared/reaction/regime.cjs

classifyRegime(spot, nearS, nearR, containment, adx, atrPct, {candles}) → { regime, confidence, trendIntoZone }

7. Strategy Bias Selection

7a. Position in Range

posInRange = (spot − supportZone.lo) / (resistanceZone.hi − supportZone.lo)

0.00 = at support rail
0.50 = centred
1.00 = at resistance rail

7c. Rules

  • Symmetric condor only at centre — never when spot is at a rail
  • Debit rule — debit spreads only when IV/RV ≤ 1.0 (premium is cheap)
  • No_trade for trend-into-zone — falling knife / breakout risk
  • Each suggestion includes structureGeometry (skew, bodyAnchor, testedRail) for future leg-builder integration

13. What Does NOT Happen on This Page

  • No LLM calls — everything is deterministic, pure functions
  • No option legs — the page suggests a structure (e.g. "Bull Put Spread") but does not construct specific strikes. That's the leg-builder's job (api/src/tools/leg-builder.ts)
  • No live API calls — reads pre-computed R2 data only
  • No Firestore writes — read-only workbench tool
