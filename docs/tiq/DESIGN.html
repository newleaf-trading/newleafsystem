02Principles

No LLM in the number path

Item scores, category scores, TQ, percentile, rank, calibration, simulator P&L and every diagram are pure deterministic code in shared/tiq/. Models may only write item/scenario text, offline.

Pure & testable

The engine is CommonJS, no network, no Firestore, no DOM, no Date.now() in scoring (timestamps injected). Every export tested in isolation.

Append-only & provenance

Sittings and sim sessions are append-only — a retake is a new document. Every Firestore write carries a nested provenance envelope.

Honesty over flattery

Cohort floors (n≥30 to norm, n≥500 to rank) are enforced in code; anchor-based TQ is capped at 130; percentiles degrade to a criterion band rather than fabricate precision.

03The engine — shared/tiq/

Patterned on shared/plan: own package, colocated *.test.js (plain node:assert), hand-written .d.ts, and a sync.js drift guard.

Drift guard

The static Workbench has no bundler, so the browser loads a generated copy of the engine. sync.js --check fails the build if the browser copy has drifted from the Node source — otherwise the browser and server could score differently.

04Scoring contract

# per-category, then blended
category_c = 100 × Σ earned / Σ max
composite  = 0.18·KQ + 0.24·EQ + 0.20·SQ + 0.28·RQ + 0.10·MQ
TQ         = 100 + 15·z(composite)      # anchor table (capped 130) until n≥500, then empirical

# the ruin gate — caps, never raises
if RQ < 45 or ruin_flags ≥ 2 → TQ = min(TQ, 95), banner "Capital preservation risk"

# percentile — mid-rank, clamped, suppressed below cohort floors
percentile = 100 × (below + 0.5·equal) / n

RQ carries the largest weight and KQ the second-smallest on purpose: knowledge is the cheapest of the five to acquire and the least predictive of survival.

05Content & validation

content/tiq/ is the source of truth; Firestore is a seeded mirror. Edit the JSON and re-seed — never the console.

  • bank-v1.json — 40 assessment items, five categories, framing pairs, ruin flags, trait loadings.
  • frontdoor-v1.json — 12-item Instinct quiz + 6 archetypes.
  • scenarios/the-wednesday.json — the simulator scenario (scripts, rules, nodes).
  • scripts/tiq/validate-bank.js — 10 invariant rules (duplicate ids, choice/scoring key match, one clear best answer, ≥3-pt gap for knowledge items, framing-pair parity, category validity, ruin-flag validity, front-door consensus sums to 100). Runs pre-commit and pre-deploy.

Rule 4 exemption

The "best vs second-best ≥ 3 points" gap is scoped to knowledge-type items; behavioural EQ items are exempt, because the bank deliberately grades their distractors close so there are no free wrong answers.

06API — api/src/routes/tiq.ts

All scoring is server-side. Item sequences are served with the answer key, scoring blocks and explanations stripped — a client that could see the key before answering makes the instrument worthless.

07Auth

The middleware accepts two credentials. API key (X-API-Key) for services, and a Firebase ID token (Authorization: Bearer) for signed-in browser sessions — the workbench nav exposes the token (window.__nlGetIdToken), so the surfaces authenticate automatically with no manual key. A verified user maps to their custom-claim role, or free.

08Firestore security

The append-only / server-side guarantees are only real if a client can't reach the collections directly. A blanket allow read: if true catch-all was replaced with a collection-bound one so the sensitive collections could be carved out.

CollectionClient access
tiqSittingsread own document only · no client write
tiqItems (holds the key)server only
tiqItemsPublic (stripped)read
tiqScenarios (holds sim points)server only
tiqSimSessionsread own · no client write
tiqBanks · tiqNorms · tiqItemStatsread-only

Verified with a rules test against the emulator (16/16), including the assertion that a client-authenticated write to tiqSittings is denied.

09Question diagrams — tiqVisuals.js

Text-only trading scenarios are hard to parse, so 28 of 40 questions carry a visual spec rendered as inline SVG — computed from the question's own numbers, nothing generated. AI image generation was rejected: a trading diagram must be numerically exact.

Purely-judgement items get no diagram. The style was prototyped in Remotion and ported to live SVG for a responsive, always-correct page render.

Custom-domain routing (found & fixed live)

The static surfaces call the API by absolute function URL on any deployed host — the hosting has no /api→function rewrite, so a relative /api on newleafsystem.com served the SPA and broke the page. Clean-URL rewrites (/workbench/tiq → tiq.html) were also added so the paths resolve to the static pages instead of the SPA's 404.

12Decisions & gotchas

  • Anchor TQ capped at 130 — TQ 130 is already +2σ; a table with no cohort behind it cannot justify a three-sigma claim. Empirical z-scoring lifts the cap at n≥500.
  • forced_choice_vector removed — named in the brief but defined nowhere and used by no item; trait_loadings already does that job.
  • tiqScenarios is server-only — the scoring key moved into the scenario documents, so the security posture had to move with it.
  • Integer pence — simulator P&L is computed in pence so path-independence is exact by construction, not float luck.
  • Named-database trap — the namespaced admin.firestore(app, dbId) silently ignores the id and writes to (default); auth and the route read the named newleafdb via the modular getFirestore. A first prod seed landed in the wrong database until the seed switched to the modular API.
  • JDK 24 — firebase-tools' emulator needs JDK 21+; the machine default is Java 11, so JAVA_HOME points at the installed OpenJDK 24 for the emulator tests.
