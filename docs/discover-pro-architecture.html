3. Side-by-Side Comparison

Before (Discover)
  • 5-stage wizard (multi-step)
  • 1 LLM call for explanation (40 words)
  • No thesis, no risk, no exit plan
  • No position sizing
  • No conviction scoring
  • Legs without mid prices
  • Market read independent of engine direction
  • Canvas payoff chart (DPI issues)
  • claude-sonnet for recommend ($0.01/call)
  • ~4.5s total latency
After (Discover Pro)
  • Single scrollable page
  • 7 LLM calls (1 explain + 6 reasoning, parallel)
  • Full thesis + risk + exit + regime + sizing
  • Computed position sizing (2% risk target)
  • Conviction 1-10 + letter grade A-D
  • Legs with real bid/ask/mid from chain
  • Market read constrained to engine direction
  • Highcharts payoff + P&L heatmap
  • qwen-plus for explain ($0.001/call)
  • ~5s total latency (parallel reasoning)

7. Key Design Decisions

Decision 1: Numbers are computed, narratives are reasoned

Early versions asked the LLM to generate P&L numbers. The LLM consistently failed at multi-leg options math — getting wrong signs, missing ITM legs, inventing credits. We moved all arithmetic to legMath.js (client-side) and restricted the LLM to qualitative analysis: thesis conviction, risk scenario descriptions, exit reasoning.

Rule: If the answer has a formula, compute it. If it requires judgment, reason about it.

Decision 2: Parallel reasoning, not sequential

All 6 reasoning calls fire simultaneously via Promise.all(). Wall-clock time = slowest single call (~3s), not the sum (~18s). This makes deep analysis feasible in a real-time UI without making users wait.

Decision 3: Keep the engine, don't replace it

The deterministic engine (strategy-engine.js) selects strategies through auditable gates. An LLM would hallucinate strategy selections, be non-reproducible, and cost 100x more. The engine decides; the reasoning layer explains and enriches that decision.

Decision 4: Real mids from the chain, not estimates

The /api/recommend route already fetches the full option chain from Alpaca. We added a post-processing step to match each selected leg to its chain contract and attach the real bid/ask/mid/iv. This eliminated the estimated-mids problem that was producing arbitrage-like payoffs.

Decision 5: Direction-aware market read

The original flow ran ai-read before recommend. The market read didn't know the engine would pick a bearish strategy, so it often said "bullish, buy calls." We reordered: recommend runs first, then ai-read receives engineDirection so its output is consistent.

Decision 6: New page, not enhanced existing

Discover is a 3,070-line multi-stage wizard serving all users. Adding 6 reasoning panels would make it unwieldy. Discover Pro is a separate product — single-page, scroll-based, aimed at users who want institutional-grade analysis. The existing Discover page is completely unchanged.

8. Interview Talking Points

System Design
  • Separation of concerns: Engine (deterministic, 30ms) decides. LLM (reasoning, 3s) explains. Code (legMath.js, <1ms) computes. Each does what it's best at.
  • Model tiering: Benchmarked 5 models, selected qwen-plus (fast, $0.80/M) for narration and qwen3-max (reasoning, $2/M) for analysis. 10x depth increase for +47% cost.
  • Parallel execution: 6 LLM calls via Promise.all() — wall-clock equals slowest call, not sum. Free depth in latency terms.
  • Caching strategy: 15-min cache by ticker+expiry. Most users view same top picks within minutes → effective cost drops 70%.
Hard Lessons
  • LLMs cannot do options math. They get simple cases right but fail on multi-leg intrinsic value calculations, ITM legs, and butterfly payoffs. We moved all P&L computation to deterministic code and restricted the LLM to qualitative analysis.
  • Estimated pricing creates impossible trades. A distance-based mid estimation formula produced a BWB with $176-$676 profit everywhere and zero loss — a risk-free arbitrage that doesn't exist. Real chain mids from the API fixed this.
  • Internal consistency is harder than any single feature. Market read, thesis, risk, exit, sizing, chart, heatmap, and metrics must all agree on direction, leg types, and numbers. We enforced this through prompt rules, computed overrides, and a "reference bar" showing the real numbers.
Technical Highlights
  • BWB post-parse validation: LLM picks symmetric wings (regular butterfly). Code detects equal widths and automatically widens the broken wing. Belt-and-suspenders: prompt instruction + code validation.
  • Structure classification: The reasoning engine classifies each trade as "put-side broken wing butterfly | 4 legs | DEFINED RISK" and injects this into every prompt. Prevents the LLM from claiming "unlimited loss" for a capped structure.
  • Computed reference bar: A bar above reasoning cards shows the real numbers (legs, credit, max P/L, breakevens). Users instantly see if LLM text contradicts the math. Trust through transparency.
  • Model assignment system: Single source of truth (model-assignments.ts) with env-var overrides. Swap any service's model without code changes. Admin dashboard renders the table.
